## What is actually here

Eight files, 941 lines total: `index.html` (81), `css/orbital.css` (132), `js/game.js` (210, the
state/DOM orchestrator, loaded last), `js/physics.js` (112, pure and DOM-free on purpose — its own
header comment says it "attaches to globalThis so it also loads under Node for the solvability
tests," which don't exist yet, see task one), `js/render.js` (206, all canvas drawing plus the frame
loop), `js/input.js` (64, delta-based drag aiming plus keyboard), `js/levels/pack-01-basics.js`
(58, 10 levels) and `js/levels/pack-02-deepspace.js` (78, 11 levels). 21 levels across two packs,
941 lines, zero offsite requests (confirmed by direct grep across every owned file — no
`fonts.googleapis.com`, `fonts.gstatic.com`, `cdnjs.cloudflare.com`, or `cdn.jsdelivr.net` hit).

**Fonts are vendored, not hotlinked.** Five woff2 files in `fonts/` (Space Grotesk 400/500/700,
Space Mono 400/700), sourced from the `@fontsource` packages, SIL OFL 1.1 licensed, with a README
that says plainly the original build hotlinked both families and the board's integrity check is
why they're vendored now — matches this repo's standard pattern exactly.

**The physics is deterministic and single-sourced on purpose.** `OrbitalPhysics.solve()` and
`.substep()` are the *same* stepper driving both the dotted aim-preview flight plan and the live
flight after launch — that's what makes the preview an honest prediction rather than a heuristic
sketch, and it's the one thing worth protecting above everything else in this codebase. Six body
types: `planet`/`star`/`rock` (attract, solid — touching one is `CRASH`), `repulse` (negative mass,
pushes away, not solid), `blackhole` (heavy attract, solid, instant `CRASH`), `wormhole` (linked
pair by a shared `link` id; entering one teleports you out the partner at the same speed, optionally
turned by `exitTurn`), `booster` (not solid, adds a velocity kick along `dir` when passed through).
Some bodies orbit (`b.orbit` — a moving centre with a period), resolved at whatever simulated time
`t` the stepper is asking about.

**Persistence is hand-rolled, not `gvb-save.js`.** One key, `orbital_progress_v2`, one entry per
level keyed by `pack.id + "#" + index` (stable across reordering or new packs, since it's never a
bare numeric index). `loadSave()` already migrates the one prior format on its own
(`orbital_progress_v1`, a flat object keyed by plain numeric index) — this project solved its own
schema-drift problem before ever touching `gvb-save.js`. Best attempt-count per level maps to a 1-3
star rating (`starsFor`: ≤1 attempt is 3 stars, ≤3 is 2, else 1).

**"Reset progress" has no confirmation.** `btnWipe`'s click handler wipes every level's stars in one
click — `progress = {}; writeSave(progress);` — no "are you sure," no undo. Every other project in
this repo that can erase real progress either gates it behind a second click/dialog or treats it as
this project's own considered decision; this one doesn't appear to be a decision, just unwritten.
Worth a look — see task list.

**No test suite exists.** Nothing but hand-testing currently verifies that any of the 21 levels are
actually winnable, that wormhole pairing/`exitTurn` behaves correctly, that a booster's kick applies
along the right vector, or that the `v1`→`v2` save migration actually round-trips.

**No preview or OG card exists.** The board notice (`data-tags="Puzzle" data-new`) has no
`data-preview` attribute, so it falls back to the shared `guild-board.png`. Nobody has captured or
promoted a screenshot.

**Mobile input already has real thought behind it, untested on a real device.** Aiming is
delta-based (the drag vector is the launch vector, so a finger never covers the probe — `beginAim`/
`moveAim` in `input.js`), there's a portrait-rotate gate keyed off `matchMedia("(pointer:coarse)")`,
and the CSS has a dedicated `@media (pointer:coarse)` block for larger touch targets. None of this
has been verified at a real narrow viewport or with real touch/pointer events yet.

## Your task

1. **Build a test suite, starting with the physics module — it's already written to make this
   cheap.** `js/physics.js` is pure and DOM-free by design, loads under plain Node, and its own
