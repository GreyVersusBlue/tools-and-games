## House rules for every file in this repo

- **No build step.** Static files served by GitHub Pages from the repo root at
  `greyversusblue.com`. Plain ES modules, no bundler, no transpiler, no runtime npm
  dependency. `tools/seed_data.py` is a dev-time script, which is fine; nothing in a
  browser may need it.
- **Zero offsite requests.** Every dependency gets vendored into the project.
- **Each project vendors its own copy; nothing is shared across projects** (locked
  decision #17). `assets/js/gvb-save.js` is the one deliberate exception in the whole
  repo, and it is shared by import, not by copying.
- **Never change a storage key** (locked decision #36). Yours is `closingTime.save.v1`.
  **It keeps that name.** Changing it silently abandons everyone mid-career. Unversioned
  saves read as version 0 and come through `repair`.
- **`migrate` is for version drift; `repair` is for every load** (locked decision #37).
- **Windows is the dev machine** (v7 §7). An absolute `import()` path needs
  `pathToFileURL` — a bare `C:\...` is read by Node as URL scheme `c:` and refused
  outright. `tools/smoke.mjs` imports your modules under plain Node, so this is live for
  you.
- **A check that only prints is a check that gets ignored** (locked decision #13). Your
  smoke suite must exit non-zero on failure.
- **Verify a guard-rail by reintroducing the bug it guards** (locked decision #34). Two
  versions of a line-of-sight check once passed the whole suite while doing nothing at
  all. If you add a test, break the thing on purpose and watch it fail first.
- **Assert against the DOM for anything that just happened, and against the save only
  for what a reload has to survive** (locked decision #39). **This rule was partly
  written about your game: Closing Time saves on render.**

## What is actually here

A turn-based management sim in a proper module layout — `js/engine/` and `js/ui/`
subfolders, six data categories behind `data/manifest.json`, a Python seeder, and its own
Node smoke suite (`node tools/smoke.mjs` → `SMOKE OK`). Tagged `Sim` on the board with a
preview and OG card. `npm run games` drives it: renders all six desk screens, ends 14
days handling event modals along the way, and reloads mid-career.

**The save system is hand-rolled and unsafe.** From v7 §11 verbatim: it has a
`save()`/`loadSave()`/`wipeSave()` on `closingTime.save.v1` **with no version stamp and no
validation at all — a corrupt blob is `JSON.parse`d straight into `S` and the game boots
on it.** That is the whole reason this is item one.

**It saves on render**, which is why locked decision #39 exists. Anything just-happened is
readable from the save here, unlike Integer Foundry (8-second autosave interval) or Faire
Weekend (never saves during a report phase). Don't assume that stays true after you
refactor — if it changes, say so in your notes, because `play-games.mjs` was written
against the current behaviour.

**A boot trap that already cost a session** (v7 §4, and it is not the one v6 documented):
`boot()` awaits `loadAll()` before rendering anything. So testing for `.start-screen`
without waiting first finds neither the modal nor the nav, then waits out the full
timeout on a nav that is never coming. Wait for `'.start-screen, #nav [data-nav]'` —
whichever arrives.

**It hotlinks three Google Font families** — IBM Plex Mono, Public Sans and Zilla Slab —
at `index.html` lines 24 and 26. v7 §5 claims the site makes zero offsite requests
site-wide. That is wrong, and the suite cannot see it: `prepPage()` in
`Tools/board-check/harness.mjs` *fulfills* Google Fonts requests locally from bundled
`@fontsource` packages before the blocked-list check runs, so font hotlinks never reach
`page.__blocked`. All three families are already on disk in
`Tools/board-check/node_modules/@fontsource/` — copy woff2 files out, but nothing at
runtime may reference `node_modules`.

## Your task

**Task one, the headline: adopt `assets/js/gvb-save.js`.**

What the game gets, from v7 §1: file export/import of a career, a memory-backed fallback
for browsers that block storage, and one implementation of "refuse to load garbage"
instead of none. What the repo gets: a second adopter, which is how you find out whether
the module's shape is right or whether The Fourth Quarter just happened to fit it.

Specifics that will bite you, all learned the expensive way last session:

- **Keep the key `closingTime.save.v1`** (locked decision #36).
- **`defaults` may be a factory, and probably has to be.** If the initial career state
  involves anything randomised — rolled clients, a starting listing set, a seeded market
  — day one cannot be a literal, and passing one means `slot.reset()` hands back `null`
  and the module is useless to you. This exact gap was found by The Fourth Quarter's
  three random job applicants.
- **`repair` runs on every accepted load; `migrate` only on version drift** (locked
  decision #37). The fill-in-the-gaps pass that currently lives in your `loadSave()`
  belongs in `repair`, not `migrate`, because it has to run on every accepted load from
  every door — localStorage, an imported file, a pasted blob, and a save the current
  build just wrote. Read `repairCampaign()` in `Projects/fourth-quarter/js/campaign.js`.
  This is the hook that did not exist until last session, and it exists because every
  project's own `load()` already had a pass with exactly this shape.
- **The bug class `repair` catches**, so you know what to look for: The Fourth Quarter had
  a staffer saved before roles existed. The old loader filled in `role` and `skill` but
  never `speed`, and `beginNight()` multiplied that straight into metres per second — an
  `undefined` there made a floor NPC with a NaN speed that never arrives anywhere.
  **Go looking for your equivalent.** Any field added to `S` since the game shipped, that
  an old save won't have, that gets used in arithmetic. Enumerate them.
- **`mountSaveBar` takes a `buttons` option** (`["export", "import"]`, etc.) and each
  button carries `data-gvb="export|import|reset"` so a driver can click it without
  depending on label text or order.
- **Put the save bar somewhere reachable during play.** v7 §9 flags that The Fourth
  Quarter's lives only on the start screen, so exporting mid-week means reloading the
  page to get the overlay back. Nothing is lost but it is a step nobody should have to
  think of, and it is still open as item 2 on the next-session list. You have six desk
  screens and a day-end cycle — put it somewhere sensible the first time.
- **Import the module relatively** — `../../assets/js/gvb-save.js`, not
  `/assets/js/gvb-save.js`. `tools/smoke.mjs` imports your modules under plain Node,
  which cannot resolve a leading slash. This is exactly why The Fourth Quarter's import
  is relative.
- **Don't touch `localStorage` directly anywhere afterwards, including in `main.js`.**
  Reading that property *throws outright* in a browser configured to block storage, which
  is the exact case the module's memory fallback exists to survive. Let `gvb-save` do the
  probing. Pass a stub in tests.
- **A missing hook is a Shared-file request, not an edit.**
