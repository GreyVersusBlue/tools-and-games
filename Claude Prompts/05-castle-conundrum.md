## Project-specific rules you must not relitigate

These are locked. Read the reasoning in the handoff sections cited before you form an
opinion, and if you still disagree, put it in your notes rather than acting on it.

- **#15** `modelPath` on an NPC def is honoured generically in `npc.js`. The class does
  not hardcode which model belongs to which NPC id. Assigning a real model is a
  `data/npcs.json` edit, not a code change. Don't special-case NPC ids in `build()`.
  Extended this round: `.glb` vs `.gltf` is likewise not keyed off anything — the NPC
  loader is generic over the model file's extension too.
- **#16** `getDialogueLines()` returns the raw array with the `{RIDDLE}` token intact.
  Substitution is `quest-manager.js`'s job.
- **#21** The casting is `King`→Guard, `Adventurer`→Scholar, `Farmer`→Wizard, and the
  filenames are actively misleading about why. v5 §1 has the visual reasoning.
- **#22** `hideMaterials` / `hideNodes` on an NPC def are the sanctioned way to subtract
  from a cast model.
- **#23** Anything rigged goes through `loadGLTF()` and clones via `SkeletonUtils`.
  **Never `Object3D.clone()` a `SkinnedMesh`**.
- **#24** Held props are aimed from rig geometry, tip following the fingers.
- **#26** NPC positions get checked against geometry, not just against the interact
  prompt. Interaction is proximity plus facing with **no line-of-sight test**.
- **#27** `play-castle.mjs` runs **headed on purpose**. Don't optimise it back to
  headless: pointer lock and GPU rendering both need real compositing, and the failure
  mode is a hang, not an error.
- **#33** Occlusion tests go against the mesh tree, not `castle.colliders`. Decorative
  geometry can be `noCollide` — the gate arch is.
- **#35** Direct `camera.rotation` writes only work where `PointerLockControls` does.
  Use `lookAt`, and prefer it over `turnBy`.
- **The scale-normalization rule for this kit's models** (round 2): every piece
  in the Kenney kit is 1 unit deep in Z, including the ones that are half-something in
  another dimension (`wall-half.glb` is half-*width*, `wall-low.glb` is half-*height*).
  Z is the dimension that's never the odd one out. `normalizeToTile()` scales off
  `size.z`, not `size.x`, for exactly this reason — don't revert that without re-deriving
  why it changed (round 2's notes have the full geometry proof).
- **New this round — a rotated piece's world-space bounding box does not shift by a naive
  straight-line offset off its own local axes.** `castle-builder.js`'s gate pivot formula used to
  assume the door swings from world x-offset `[0, size.x]`, true only at `rotationY = 0`; this gate's
  `rotationY: 180` (matching the flanking wall runs) flips that range in world space, so the
  un-rotated formula put the whole leaf off the archway entirely. Fixed to
  `gatePos.x - (size.x/2)*cos(rotY)` with a matching `sin(rotY)` term on `z`, general over any
  `rotationY`, not just 0/180. If you add another rotated piece with a position formula, check it
  against this the same way, don't assume `rotationY = 0`.
- **New this round — furniture and NPCs need checking against the wall *behind* them, not just
  against each other.** Four objects (table, statue, a cabinet, a commode) were sealed in wall
  geometry and nobody had measured that corner before; the Scholar's own body clipped the wall at his
  old position too. `play-castle.mjs`'s wall-clearance beat name-matches against `wall`/`wall-half`/
  `tower`/`column` top-level scene groups — **not** a height threshold (a height-based "anything
  tall counts as a wall" heuristic reported furniture as embedded against itself, since the furniture
  itself was taller than the threshold). Any new furniture or NPC placement should be checked against
  this beat, not just against the nearest piece of furniture.

## What is actually here

The largest project in the repo. Nine `src/` modules, three `data/` files, its own
vendored three.js with an `addons/` tree, and an `assets/` folder holding the
Kenney retro-fantasy kit, NPC models, and Poly Haven textures. Tagged
`Puzzle Explore` and `data-new` on the board.

**The blurry walls were a texture-sampling bug, not a UV or resolution problem** (round 1,
`src/assets.js`'s `setTextureQuality`/`tuneTexture`/`tuneMaterials`). Don't re-diagnose this as UV
stretching — see required reading above.

**Round 1 also fixed:** the Scholar standing inside the hall table, all three braziers sealed
inside wall geometry, and the candelabra floating above the table on an untuned offset.

**Round 2 shrank what ships: 46.39 MB → 29.46 MB over 116 requests.** Two wins: the three NPC
`.gltf` files converted to `.glb` (base64 unpacking removed, saved 4.93 MB — about double round 1's
own estimate), and four Poly Haven prop kits' 1k texture sets downsampled to 512 (measured
before/after with real in-game screenshots first, per locked decision #42 — no visible difference
at the distance any of them are actually seen, including `wooden_gate`, which never appears in
frame at all — see the gate bug below).

**Round 2 also rebuilt the interior hall at the kit's real scale.** `normalizeToTile()` was scaling
`wall-half.glb` off its X dimension, which gave it 8m height/depth instead of 4m (see the new
project-specific rule above) — the hall doorway was an 8m tunnel and the hall's texel density was
half the outer walls'. Fixed, with the wall-run spacing in `data/scene-config.json` corrected to
match (halved step, doubled count on all four wall-half runs). **No repositioning was needed** —
better than round 1's own note anticipated — the Scholar, hall brazier, and furniture all happened
to still clear the corrected geometry. `column.glb` got an explicit height-normalize (was 1m tall,
20cm thick; now 4m tall, 80cm thick, visible floor-to-ceiling supports). Braziers got real
colliders (`castle.addCollider(stand, 'brazier')`) — all three now block movement.

It has its own end-to-end play test, `npm run play` (`Tools/board-check/play-castle.mjs` — **yours**),
which as of this refresh runs **34 beats** (up from 32 — this round added the wall-clearance and
gate-arch beats, each verified by breaking it on purpose first per locked decision #34) and plays
the game through to victory, all passing. Confirmed independently this refresh, real Chrome via
Playwright, all 34 beats green, real movement throughout. It is deliberately excluded from
`npm run games` — this one goes deep on one game instead.

**Ship weight: 29.46 MB over 116 requests, unchanged this round** — nothing this round's four tasks
touched affected shipped asset weight, only positions and one file (`play-castle.mjs`).
