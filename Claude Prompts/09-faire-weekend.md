## What is actually here

Five `js/` modules, one stylesheet, and an **801-assertion** Node smoke suite (was 783) that
builds a JSDOM. Tagged `Sim` and `data-new` on the board with a preview and OG card.

**Mobile tap targets are fixed, round 3.** The ≤375px breakpoint's `--cell` is 48px now (was 30px),
with buttons/tabs at a `min-height: 44px` floor — measured before/after, documented in `style.css`
comments. `#board`'s desktop layout also got `grid-template-columns: fit-content(710px)
minmax(340px, 1fr)`, a fixed worst-case cap rather than a fully adaptive one (a named, deliberate
follow-up, not an oversight — see "Your task"). The 1080px tablet breakpoint's cell size was
deliberately left untouched, a scoped exclusion, not a miss.

**The wiring audit found one more real gap even after being called "closed" last round**: `cancelMove`
had an existing case in `main.js` (not new this round) that had never actually been click-tested.
Reinforces that the audit needs to keep repeating when a new `data-action` lands, not that it's a
one-time job.

**`gvb-save.js` is adopted, and it held to round 1's plan exactly** — key unchanged
(`renn-faire-sim-save-v1`), `validate` lifted unchanged, everything `loadState` used to fill in
now lives in `repair`, `defaults: createInitialState` as a factory, imported relatively, save bar
mounted in `#footer` (`buttons: ['export', 'import']`). The one gap round 1's plan didn't call out
— because it's about the test suite, not the module — was fixed too: `tests/smoke.mjs` used to risk
a save slot getting cached across a simulated "reload" if built once at module scope; fixed by
building it fresh on every call.

**The weekend has a real shape.** A `WEEKEND_DAY_ATTENDANCE` table (Friday 0.85x, Saturday 1.2x,
Sunday 0.95x) and one new term in `simulateDay`'s attendance formula. A tooltip on the ledger's
Weekend/day HUD item names the multiplier, so the lever isn't invisible on screen — directly
answering the report-phase work's own warning against shipping an invisible lever.

**Ten previously-unclicked player actions are now driven through real clicks**, not just engine
calls: `contract`, `release`, `hireVendor`'s day-rate let-go path, `launchCampaign`,
`autoFillStalls`, `unassignVendor`, `demolishPlot`, `selectMove`/`moveTo`,
`deletePlanningPlot`, `renamePlot` — plus the ticket-price slider and both `<select>`s, which
dispatch on a different event path (`change`/`input`) than any click-driven test ever touched
before. New Section 22 in `tests/smoke.mjs`, 40 assertions, each preloading a purpose-built save via
real `State.*` action functions so every action has a legitimate precondition. Closes with a
round-trip test of the save bar itself.
