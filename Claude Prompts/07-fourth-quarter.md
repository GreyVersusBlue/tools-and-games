## House rules for every file in this repo

- **No build step.** Static files served by GitHub Pages from the repo root at
  `greyversusblue.com`. Plain ES modules, no bundler, no transpiler, no runtime npm
  dependency.
- **Zero offsite requests.** This game already makes none and hotlinks no fonts — one of
  the few pages in the repo where that is genuinely true. Don't regress it.
- **Each project vendors its own copy; nothing is shared across projects** (locked
  decision #17). This project and Aphelion both happen to be on three@0.160.0 and their
  `libs/three.module.js` are separate files on purpose.
- **Never change a storage key** (locked decision #36). Yours is `fq3d-save` and it stayed
  the same through last session's adoption specifically so every campaign saved by an
  older build still loads. Those saves carry no version stamp, which `normalize()` reads
  as version 0.
- **`migrate` is for version drift; `repair` is for every load** (locked decision #37).
- **Import `gvb-save` relatively** — `../../../assets/js/gvb-save.js`, not
  `/assets/js/gvb-save.js`. `test/smoke-campaign.mjs` imports `campaign.js` under plain
  Node, which cannot resolve a leading slash. This is already correct; don't "tidy" it.
- **Nothing in this project touches `localStorage` directly any more, including
  `main.js`.** Reading that property throws outright in a browser configured to block
  storage, which is the exact case the module's memory fallback exists to survive. That is
  why `campaignSlot()` takes no argument in the game and lets `gvb-save` do the probing.
  Tests pass a stub. Keep it that way.
- **Anything rigged goes through `loadGLTF()` and clones via `SkeletonUtils`** (locked
  decision #23). Never `Object3D.clone()` a `SkinnedMesh`.
- **Direct `camera.rotation` writes only work where `PointerLockControls` does** (locked
  decision #35). This project owns the camera's rotation and rewrites it every frame, so
  use `lookAt`, and prefer it over `turnBy` because Playwright clicks under pointer lock
  silently accumulate yaw and pitch drift.
- **Windows is the dev machine** (v7 §7). Absolute `import()` paths need `pathToFileURL`.
- **A check that only prints is a check that gets ignored** (locked decision #13).
- **Verify a guard-rail by reintroducing the bug it guards** (locked decision #34).
- **Assert against the DOM for anything that just happened, and against the save only for
  what a reload has to survive** (locked decision #39).

**The legacy-save audit is done.** `repairCampaign()` in `js/campaign.js` is now built

or logged); `cash` missing (the distributor gave away 100,000 beers for free, then the till

throw in the set); `skill` non-numeric; `upgrades` not an array. Both suites assert all 14
reintroduced-bug guard-rails (locked decision #34) — put each bug back exactly as it used to
be, confirm it fails, then restore the fix.

**It is the shared save module's reference adopter, not just its first.** `js/campaign.js`
still persists through `assets/js/gvb-save.js` on the key `fq3d-save`, unchanged since
session 7 (locked decision #36). Ten other projects adopted the module last round; the five
real gaps their adoptions found are already fixed in the module (`gvb-site-handoff-v8.md`
§4) and none of them required a change here.

**A dev-menu "Skip to last call" button exists now.** Before it, the box score — which now
hosts a save bar — was reachable only by playing a full night (six real minutes at 1x, and
the speed-up buttons can't be clicked while pointer lock is active). It pushes `engine.t` to
just under eight hours and lets the real closing path run, so it produces a genuine box
score rather than a faked one.

`npm run games` drives the whole save story here, including the two new mounts: bar
present, ladder warps, export, reload, import, legacy save, New Game, doors open,
door-panel export, dev-menu box-score skip, box-score import. Two traps in that suite worth
knowing because they are about your code:

- **A file picker has to be answered before it is opened.** `promptImport()` creates a
  hidden `<input type="file">` and clicks it. Playwright wants
  `page.waitForEvent('filechooser')` registered *before* the click; Puppeteer wants
  `waitForFileChooser()`. `prepPage()` sets `page.__engine` so a script can tell. The
  export side needs no engine knowledge — hooking `URL.createObjectURL` reads the exact
  bytes a download would have written, and neutering the anchor click stops the browser
  saving a file. If you change how import is triggered, that suite breaks, and fixing it
  is a Shared-file request.
- **`games.mjs` no longer clicks `#wipeBtn`** to get a clean start. `enter()` clears the
  storage key *before the page that reads it boots*, then reloads. Clearing without a
  reload does nothing, because the module has already read the save and built its
  campaign. Also, this game's entry recipe carries `start: false`, because the save bar
  lives on the start overlay and the regression suite needs it up while a screenshot needs
  it gone. Prompt 21's application of the door-panel/box-score beats needed two further
  sequencing fixes on top of the original request: the dev menu's box-score skip only works
  once a night is actually running, and `#wipeBtn` only exists on the start overlay, reached
  by a reload, not by a click mid-campaign.

## Your task

**Task one, the headline: give the venue ladder a door into the game.**

`moveVenue()`, `canMoveVenue()`, `nextVenue()` and `settleDarkNight()` are all written and
tested — the Node suite covers the whole ladder — and completely unreachable in the shipped
game. There is no Real Estate station in `day.js`, and `main.js` already passes
`onMove: rebuildVenue` and `closedNight` into `DayPhase`, neither of which is ever called.
The only way a player currently reaches the Fieldhouse is the dev menu's warp, which is free
and skips the dark nights entirely. So the cash gates ($5,500 / $15,000 / $34,000), the
one-way lease, and the dark-night settlement are all dead content: four tiers of
already-written, already-tested game that nobody who plays normally will ever see.

Build a Real Estate station in `day.js` that calls `C.moveVenue()` through the `onMove`
callback and drives the dark-night settlement through `closedNight` — both callbacks are
already wired in `main.js`, so this is a UI and flow problem, not an economics or testing
problem. Assert the whole path in both Node suites and in `play-games.mjs` if you touch
anything a browser suite should see.

**Task two: fix the seat count, which becomes a live bug the moment task one ships.**
`buildWorld()` ignores the venue-tier argument `main.js` already passes it (`buildWorld(scene,
campaign.venue)` against a `buildWorld(scene)` signature) and builds the identical 30-seat
room at every tier, so the tiers' `seats` values (30/44/60/80) never actually gate anything
— round 1 measured peak occupancy at 23 (Corner Tap) and 29 (flagship) against 30 physical
seats, so the numbers above the Corner Tap's cap are inert. This is not "the ladder is
broken" — a same-night A/B measured the flagship at 86% more net than the Corner Tap, because
rent and wages are flat and the extra crowd converts even with degraded service (60% service
rate vs 65%) — it is "the seat cap is cosmetic." Either build a real room per tier or derive
`VENUES[].seats` from the actual room (`world.seats.length`) and drop the pretense that they
differ.

**Task three: the night loop has no difficulty curve.** Nothing reads `c.day` except
`weekday()` and the HUD. Rent is a flat $110 at every tier and every day, wages are the
player's own roster, and crowd only goes up with tier — so day 40 is strictly easier than
day 4 and there is no fail state. Decide, and write down the decision, whether that is
intended (a sandbox) or whether rent should scale with tier. If you implement scaling,
assert it in `test/smoke-campaign.mjs`.

**Task four, if there is session left: convert the WAVs.** `audio/` is 14.2 MB; 12.9 MB of
that is five uncompressed WAVs (`patron-storm-out.wav` 3.7 MB, `stinger-kickoff.wav` 3.6 MB,
`qte-sizzle-loop.wav` 3.3 MB, `qte-pour-loop.wav` 2.1 MB, `stinger-final-whistle.wav`
477 KB). This is not only a size problem: `playSfx()` builds the `Audio` element on first
play, so the 3.7 MB storm-out WAV downloads mid-night, the first time a patron gives up, and
the clone is asked to play before it has buffered. Convert to OGG at the same settings as
the ten files that already are, and consider warming the cache on `beginNight()`.

**Task five, if there is still session left: wire up the mute toggle.** `setMuted()`,
`isMuted()` and `setMasterVolume()` are already exported from `js/audio.js` with zero
callers anywhere. A small control in the score bug is the whole job; the API doesn't need
anything added.

Two smaller items from round 1's notes, pick up if convenient: write one paragraph (README
or board card) stating mobile is not supported — pointer lock plus WASD plus a
keyboard-only controls hint is not a touch game, and that is a legitimate answer to write
down rather than re-litigate. And frame time was measured and is fine (median 6.9–7.0ms,
p95 spikes to 21ms at peak crowd) — don't re-measure it, just know it's recorded.
