## House rules for every file in this repo

- **No build step.** Static files served by GitHub Pages from the repo root at
  `greyversusblue.com`. Plain ES modules, no bundler, no transpiler, no runtime npm
  dependency. `tools/seed_data.py` is a dev-time script, which is fine; nothing in a
  browser may need it.
- **Zero offsite requests.** Every dependency gets vendored into the project.
- **Each project vendors its own copy; nothing is shared across projects** (locked
  decision #17). `assets/js/gvb-save.js` is the one deliberate exception in the whole
  repo, and it is shared by import, not by copying.
- **Never change a storage key** (locked decision #36). Yours is `closingTime.save.v1`.
  **It keeps that name.** Changing it silently abandons everyone mid-career. Unversioned
  saves read as version 0 and come through `repair`.
- **`migrate` is for version drift; `repair` is for every load** (locked decision #37).
  **`repair` also covers content drift, not just schema drift** (locked decision #50) —
  this project's own `assets/js/README.md` suggestion from last round, adopted
  near-verbatim into the shared doc. `repairCareer()` is where the two content-drift bugs
  described below were actually fixed.
- **`gvb-save.js`'s `fresh`/`reset` forward arguments to a `defaults` factory, and
  `clear()` erases without invoking one** (locked decision #47) — this project's own
  request, closing the brokerage-choice gap: `slot.reset()` no longer has to hand back a
  career at a hardcoded default brokerage.
- **`mountSaveBar` takes `filename` and `labels` overrides, and its import handler calls
  `setState` before writing to storage, vetoable by returning `false`** (locked decision
  #48). Not something this project asked for, but available if the footer bar's wording
  ever needs to change.
- **Two storage-construction gaps in `gvb-save.js` are fixed: `typeof localStorage` itself
  can throw, and `load()`'s `getItem` was unguarded** (locked decision #49). Found by other
  adopters, not this one, but this project's `careerSlot()` benefits the same way.
- **`page.__blocked` is "offsite and refused"; `page.__shimmed` is "offsite and fulfilled
  locally instead"** (locked decision #44). `harness.mjs`'s font shim answers a Google
  Fonts request before the blocked-list check runs, which is exactly why this project's
  fonts had to be checked by grep, not by `npm run games`, before they were vendored.
  `check-integrity.mjs`'s static sweep — this project's own request last round — is what
  actually catches a hotlink now; it is part of `npm run check`.
- **Windows is the dev machine** (v7 §7). An absolute `import()` path needs
  `pathToFileURL` — a bare `C:\...` is read by Node as URL scheme `c:` and refused
  outright. `tools/smoke.mjs` imports your modules under plain Node, so this is live for
  you.
- **A check that only prints is a check that gets ignored** (locked decision #13). Your
  smoke suite must exit non-zero on failure.
- **Verify a guard-rail by reintroducing the bug it guards** (locked decision #34). Two
  versions of a line-of-sight check once passed the whole suite while doing nothing at
  all. If you add a test, break the thing on purpose and watch it fail first.
- **Assert against the DOM for anything that just happened, and against the save only
  for what a reload has to survive** (locked decision #39). **This rule was partly
  written about your game: Closing Time saves on render.**

## What is actually here

A turn-based management sim in a proper module layout — `js/engine/` and `js/ui/`
subfolders, six data categories behind `data/manifest.json`, a Python seeder, and its own
Node smoke suite. Tagged `Sim` on the board with a preview and OG card. `npm run games`
drives it: renders all six desk screens, ends days handling event modals along the way,
exercises the footer save bar (export, import, a corrupt save, a legacy save), and reloads
mid-career.

**The save system is `assets/js/gvb-save.js`, adopted, and the adoption is done.** Key
unchanged: `closingTime.save.v1`. `js/state.js` exports `makeCareer(brokerageId)` (the
`defaults` factory), `validCareer(s)` (the gate: finite `day` and `cash`, a string
`brokerageId`, an array `clients`), `repairCareer(s)` (the fill-in pass, handed to the
slot as `repair`) and `careerSlot(storage)` (cached per storage in a `WeakMap`, mirroring
The Fourth Quarter's `campaignSlot`). **Zero direct `localStorage` reads remain anywhere
in the project.** A corrupt or unparseable save now lands you on the brokerage-choice
screen with Import still offered, not booted straight into garbage.

**Two content-drift bugs were found and fixed, historical now, not open:** (1) a listing
added to `data/` after a career started used to throw on the MLS board (`Cannot read
properties of undefined (reading 'status')`, the whole screen failing to render), because
`renderMLS` reads `S.listingsState[l.id]` for every listing in the DB and an old save has
no entry for content that didn't exist yet; (2) a neighborhood added after a career
started used to freeze that neighborhood's market prices forever via NaN propagation
(`Math.max(0.7, NaN)` is `NaN`, and `NaN || 1` reads as the falsy branch, so the symptom
looked like a stale price rather than a crash). Both are content drift, not schema drift —
`repairCareer()` backfills `listingsState` and `market.nb` for anything in `data/` the
save has never heard of, and it does this on every accepted load rather than only on a
version bump, which is why it caught bugs it wasn't originally written for.

**`tools/smoke.mjs` now asserts for real.** It used to print `SMOKE OK` unconditionally
and exit 0 regardless (locked decision #13 violation). It is now an assertion harness:
`node tools/smoke.mjs` → **`SMOKE OK: 76 passed`**, non-zero exit on any miss, covering the
buyer loop, the seller loop, 40 days of calendar, and the whole save path — corrupt blobs
in six shapes refused, a legacy save with nine missing fields repaired, an export
re-imported, a version-0 import re-imported, `fresh()`, `wipeSave()`.

**Fonts are vendored.** Seven local woff2 faces (Zilla Slab, Public Sans, IBM Plex Mono)
in `assets/fonts/`, 124 KB total, `@font-face` in `css/style.css`. Zero
`fonts.googleapis.com` hits remain in `index.html`. `check-integrity.mjs`'s static sweep
— added last round in direct response to this project's own request — is the check that
actually verifies this now; `npm run games` cannot, because `prepPage()` in
`harness.mjs` fulfills Google Fonts requests locally before the blocked-list check runs
(locked decision #44), so a hotlink never reaches `page.__blocked` regardless of whether
one exists.

**A boot trap still worth knowing** (v7 §4): `boot()` awaits `loadAll()` before rendering
anything. Testing for `.start-screen` without waiting first finds neither the modal nor
the nav, then waits out the full timeout on a nav that is never coming. Wait for
`'.start-screen, #nav [data-nav]'` — whichever arrives.

**It saves on render**, which is why locked decision #39 exists. Anything just-happened is
readable from the save here, unlike Integer Foundry (autosave interval) or Faire Weekend
(never saves during a report phase). Don't assume that stays true after you refactor — if
it changes, say so in your notes, because `play-games.mjs` was written against the current
behaviour.

## Your task

**Task one, the headline: give the career an ending.** Fourteen days is not a career
length and the game does not have one — `endDay()` runs forever, the ladder tops out at
Managing Broker (1,300 XP), and after that it is the same loop with bigger numbers. But
`seasonOf` in `js/state.js` already wraps at 336 days (four 84-day seasons), so a one-year
career is already encoded in the date math; nobody built the ending to match it. Ending at
day 336 with a year-end scorecard — volume, closings, referrals, final rep, the ladder
rung reached — gives the XP curve something to be a curve toward. This is the difference
between a sim and a toy, and it is cheap to build: the season math already does the hard
part.

**Task two: the topbar at 375px wide.** Six stats in a grid that wraps to four rows eats
a large share of an iPhone viewport before any content renders. Date/Slots/Cash on one
line, with Rep/XP/Rate behind a tap, would roughly halve it. This is the single biggest
thing between the game and being playable on a phone; the rest of the layout already
behaves at that width.

**Task three: the Ledger tab is the weakest of the six desk screens.** It is
`logPanel(80)` where Desk already shows `logPanel(8)` — the same list, longer. Either give
it a real filter (money only / reputation only / this-client-only) or fold it into Desk as
a "show more" and free the tab slot for something with actual state in it.

**Task four: `data/` extensibility, the untested reverse direction.** Adding content to
`data/` after a career starts is now safe (`repairCareer()` backfills it). Removing
content while a save references it is not: `S.listingsState` keeps the orphan entry,
`calendar.js` ages a listing that no longer exists, and the price-cut log line throws on
`DB.listings[id].address`. Same family of bug as the two already fixed, opposite
direction, cheap to fix in the same function.

**If there is session left:** anything else your own audit turns up. Worth a fresh look:
whether the six desk screens (now five plus a folded Ledger, if task three lands) earn
their space, and whether any other `S` field added since last round needs a line in
`repairCareer()`.
