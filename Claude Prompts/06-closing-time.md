## House rules for every file in this repo

- **No build step.** Static files served by GitHub Pages from the repo root at
  `greyversusblue.com`. Plain ES modules, no bundler, no transpiler, no runtime npm
  dependency. `tools/seed_data.py` is a dev-time script.
- **Zero offsite requests.** Every dependency gets vendored into the project.
- **Each project vendors its own copy; nothing is shared across projects** (locked
  decision #17). `assets/js/gvb-save.js` is the one deliberate exception in the whole
  repo, and it is shared by import, not by copying.
- **Never change a storage key** (locked decision #36). Yours is `closingTime.save.v1`.
- **`migrate` is for version drift; `repair` is for every load** (locked decision #37).
  **`repair` also covers content drift, not just schema drift** (locked decision #50) —
  this project's own request, now closed both directions (content added since a save was
  written, and content removed while a save references it).
- **`gvb-save.js`'s `fresh`/`reset` forward arguments to a `defaults` factory, and
  `clear()` erases without invoking one** (locked decision #47) — this project's own
  request, applied.
- **`mountSaveBar` takes `filename` and `labels` overrides** (locked decision #48).
- **Two storage-construction gaps in `gvb-save.js` are fixed: `typeof localStorage` itself
  can throw, and `load()`'s `getItem` was unguarded** (locked decision #49).
- **`page.__blocked` is "offsite and refused"; `page.__shimmed` is "offsite and fulfilled
  locally instead"** (locked decision #44). `check-integrity.mjs`'s static sweep is what
  actually catches a hotlink; it is part of `npm run check`.
- **Windows is the dev machine** (v7 §7). An absolute `import()` path needs
  `pathToFileURL`. `tools/smoke.mjs` imports your modules under plain Node, so this is
  live for you.
- **A check that only prints is a check that gets ignored** (locked decision #13).
- **Verify a guard-rail by reintroducing the bug it guards** (locked decision #34).
- **Assert against the DOM for anything that just happened, and against the save only
  for what a reload has to survive** (locked decision #39). This rule was partly written
  about your game: Closing Time saves on render.
- **A `page.waitForFunction(fn, null, opts)` call is Playwright's shape, not puppeteer-core's**
  (locked decision #52) — this project found the bug in round 2; it's fixed in every shared tooling

## What is actually here

A turn-based management sim in a proper module layout — `js/engine/` and `js/ui/`
subfolders, six data categories behind `data/manifest.json`, a Python seeder, and its own
Node smoke suite. Tagged `Sim` on the board with a preview and OG card.

**The career now ends at day 336.** `js/engine/calendar.js` exports `CAREER_LENGTH_DAYS = 336`,
matching `seasonOf`'s existing four-season wrap. `endDay()` calls `finishCareer()` on the day it's
reached instead of advancing to a 337th day — freezes a scorecard (day, volume, closings, referrals,
final reputation, level, title, cash) onto `S.scorecard`, sets `S.careerEnded = true`, and is a
no-op on any further `endDay()` call. `renderTopbar()` shows "Close out the year →" on day 336 and
"Career complete" (disabled) once ended; a `renderScorecard()` modal shows the frozen numbers,
dismissible per page load. `repairCareer()` normalizes both new fields so a pre-existing save loads
clean.

**The topbar collapses on mobile.** Below 620px, `.stat-secondary` (Reputation, XP, Rate) starts
collapsed behind a toggle; Date/Slots/Cash always show. Measured at 375×812: 241px collapsed, 301px
expanded, versus the old six-stat grid eating four wrapped rows.

**The Ledger filter now threads an exact `recId`**, not a display-name substring match. Round 3
threaded it through the ~50 `log()` call sites across `deals.js`/`seller.js`/`clients.js` — the
thing round 2 judged too large for its own filter task. Immune now to two clients whose names
collide as substrings, or a client renamed mid-career (old log lines used to keep the old name).

**Content removal is safe in both directions**, since round 2: `repairCareer()` backfills missing
entries for content *added* since a save was written, and purges entries for content *removed*
while a save still references it, in the same three maps (`listingsState`, `market.nb`,
`knowledge`). Not handled, on purpose: a deal or listing actively under contract on content that
gets deleted mid-session — documented as a known gap in the README rather than silently patched.

**The career-ending "what's next" question is answered, round 3** — read
`Claude Prompts/notes/06-closing-time-notes.md` for the exact shape shipped (a new career at the
same brokerage, or real cross-career history; confirm which by reading the notes rather than
assuming).

**`tools/smoke.mjs`** is at **105 passed** (was 100), covering the career ending, the mobile toggle,
